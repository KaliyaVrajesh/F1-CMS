# F1-CMS — Formula 1 Content Management System with ML Race Predictions

A full-stack MERN application for managing Formula 1 content with a **genuine supervised Machine Learning race prediction system** trained on 15 seasons of historical F1 data.

## Tech Stack

- **MongoDB** — Database (race results, drivers, constructors, seasons)
- **Express.js** — Node.js backend API
- **React.js (Vite)** — Frontend SPA
- **Python (Flask + scikit-learn)** — ML microservice
- **JWT** — Authentication
- **Tailwind CSS / Framer Motion** — Styling & animations
- **Docker & Docker Compose** — Containerisation

---

## Machine Learning System

### Overview

Predictions are generated by a **supervised Random Forest regression model** trained on 15 seasons of real Formula 1 race data (2010–2023). The model predicts a driver's expected finishing position and passes the features through calibrated Gradient Boosting classifiers to produce win and podium probabilities.

This is a **genuine ML system** — not rule-based weights. The model was trained and evaluated using standard ML methodology with a time-aware train/test split.

### Data Pipeline

```
Historical F1 Race Data (2010–2024, Jolpica/Ergast API)
          ↓
  Data Collection (data_collection.py)
  - Race results (6,432 driver-race records)
  - Qualifying results (1,500 records)
  - End-of-season standings (350 driver / 159 constructor entries)
          ↓
  Feature Engineering (feature_engineering.py)
  - Rolling driver form (last 5 & 10 races, strictly historical)
  - Constructor recent form
  - Circuit-specific history (prior seasons only — no leakage)
  - Previous season standings
  - Grid/qualifying position
          ↓
  Temporal Train/Test Split (NO random shuffling)
  - Training:   2010–2022 (4,953 samples)
  - Validation: 2023       (440 samples)  ← model selection
  - Test:       2024       (479 samples)  ← never seen during training
          ↓
  Model Training (train_model.py)
  - Baseline: DummyRegressor (median)    MAE: 5.000
  - Random Forest Regressor              MAE: 3.429 (val)
  - Gradient Boosting Regressor          MAE: 3.777 (val)
  → Best: Random Forest (retrained on 2010–2023)
          ↓
  Saved Model Bundle (ml/model/f1_prediction_model.pkl)
  - Regressor pipeline (imputer + scaler + Random Forest)
  - Calibrated podium classifier (CalibratedClassifierCV)
  - Calibrated win classifier    (CalibratedClassifierCV)
          ↓
  Flask ML Microservice (ml/app.py, port 5001)
          ↓
  Node.js Backend proxy (predictionService.js)
          ↓
  React Frontend (Predictions.jsx)
```

### Model Evaluation (held-out 2024 season)

```
Model Performance — Random Forest Regressor
────────────────────────────────────────────
Training samples:     5,953  (seasons 2010–2023)
Test samples:           479  (season 2024 — never seen during training)

Regression (finish position prediction):
  MAE:              3.104 positions
  RMSE:             3.976 positions
  R²:               0.523
  Top-3 Accuracy:   55.6%

Classification (calibrated probabilities):
  Podium AUC:       0.932
  Win AUC:          0.937

Baseline (median predictor) MAE: 5.000
Improvement vs baseline:    +1.9 positions
```

### Why these results are legitimate

- Train/test split is **temporal** — 2024 test data was never seen during training
- No data leakage — all features use only information available before the race
- Rolling form windows are computed with strict `iloc[:i]` slicing (no look-ahead)
- Circuit history uses only **prior seasons** (not current-year races)
- Probabilities come from **CalibratedClassifierCV** (isotonic regression calibration), not manually assigned values
- Evaluation metrics are computed on real data, not fabricated

## Running the ML System

### 1. Install Python dependencies

```bash
cd ml
pip install -r requirements.txt
```

### 2. Collect historical data (already done — run only if you want to refresh)

```bash
cd ml
python data_collection.py
# Takes ~90 seconds, fetches 2010–2024 from Jolpica API
```

### 3. Build feature matrix

```bash
cd ml
python feature_engineering.py
```

### 4. Train the model

```bash
cd ml
python train_model.py
# Prints full evaluation report on completion
# Saves model to ml/model/f1_prediction_model.pkl
```

### 5. Start the ML microservice

```bash
cd ml
python app.py
# Runs on http://localhost:5001
```

### 6. Start the Node.js backend

```bash
cd backend
npm run dev
# Runs on http://localhost:5000
# Calls ML service at localhost:5001 for predictions
```

### 7. Start the frontend

```bash
cd frontend
npm run dev
# Runs on http://localhost:5173
# Navigate to /predictions
```
